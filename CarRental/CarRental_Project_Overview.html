01 / Overview

What the application does

A lightweight web application for managing a rental fleet and customer reservations.

01

Browse fleet

View vehicles, availability, and daily rates.

02

Manage fleet

Admins add, edit, delete, and mark cars available or unavailable.

03

Book dates

Members reserve a car for a date range with overlap checks.

04

Track bookings

Members see their reservations and may cancel before the start date.

Current solution target: ASP.NET Core on .NET 10 with SQLite persistence.

MEMBER

Renter / customer

  • Register with a unique email and sign in
  • Browse fleet and daily rates

  • View own booking history and cancel eligible bookings
ADMIN

04 / Fleet operations

Admin fleet-management workflow

Fleet changes are exposed in the UI and enforced by protected API endpoints.

Vehicle record

  • Identification: make, model, year
  • Pricing: daily rate (decimal)
  • Operational state: available / unavailable

Vehicles begin available by default.

  • Add: create a car after field validation
  • Edit: update make, model, year, or rate
  • Toggle: explicitly set availability
  • Delete: blocked if booking history exists
Availability is an operational flag; date-specific reservations are separately protected against overlap.
CARRENTAL / PROJECT OVERVIEW05

05 / Booking rules

Booking, pricing & cancellation rules

Business rules are checked server-side; browser date controls are only a convenience.

DATE RANGE

Start date cannot be in the past; end date must be on or after start.

DURATION

A booking may cover at most 60 days.

AVAILABILITY

Car must exist and be marked available.

NO DOUBLE BOOKING

Confirmed reservations for the same car may not overlap.

TOTAL PRICE

Daily rate × inclusive number of calendar days.

CANCELLATION

Member may cancel only before start; Admin can cancel any booking.

Example: ₹52/day × 3 inclusive days = ₹156 booking total. Prices are displayed in INR; no taxes or external fees are modeled.

07 / Data

Core data model & relationships

A booking links one car and one Identity user; deletion rules preserve reservation history.

FLEET ENTITY

Car

  • Id (primary key)
  • Make + Model (required, max 80 chars)
  • Year
  • DailyRate (decimal, precision 10,2)
  • IsAvailable (default true)
RESERVATION ENTITY

Booking

  • Id; CarId + UserId (foreign keys)
  • StartDate + EndDate (DateOnly)
  • TotalPrice (decimal, precision 10,2)
  • Status (default Confirmed; max 20 chars)
  • CreatedAtUtc (UTC timestamp)
Composite index: (CarId, StartDate, EndDate). Car and user deletes use Restrict.

09 / Security

Identity, authorization & defensive controls

The application has baseline controls; production hardening remains necessary.

CONTROLIdentity — ASP.NET Core Identity + EF store; unique email; Admin and Member roles.
Password12+ characters with uppercase/lowercase, digit, and symbol requirements.
LockoutLock after 5 failed attempts for 15 minutes.
CookiesHttpOnly; SameSite=Strict; SecurePolicy=SameAsRequest.
AuthorizationFallback requires an authenticated user; FleetManagers=Admin; Renters=Member.
Request safetyAnti-forgery tokens on account forms; return URL restricted to local URLs.
API behaviorUnauthenticated API requests receive 401; forbidden API requests receive 403.

Important: Public registration only creates Member accounts. Configure InitialAdmin credentials through deployment secrets to provision an Admin; never store the password in source control.

11 / Reliability

Validation & expected failure paths

Invalid requests are rejected before persistence and common conflicts are explicit.

Car input

  • Make/model required; trimmed
  • Year ≥ 1886 and ≤ current year + 1
  • Daily rate > 0

Booking input

  • Start date not in past
  • End date on/after start; max 60 days
  • Car exists, available, and dates do not overlap

Safe operations

  • Delete blocked if any booking exists
  • Only owner or Admin can cancel
  • Member cancellation blocked on/after start
BadRequest: invalid rules  •  Conflict: booking/availability conflicts  •  NotFound: missing IDs  •  Forbid: access denied

16 / Project workflow

End-to-end project workflow

From sign-in to a completed reservation—or from admin login to a managed fleet.

MEMBER FLOW

Customer booking

  1. Member registers or signs in; Identity establishes a secure cookie.
  2. Browser loads the fleet from GET /api/cars.
  3. Member chooses a car and start/end dates.
  4. Booking endpoint checks dates, maximum duration, car status, and overlap.
  5. Valid booking is saved; total price and confirmation are returned.
  6. Member views bookings or cancels before the start date.
ADMIN FLOW

Fleet management

  1. Admin signs in with the Admin role.
  2. Admin adds a car or edits its make, model, year, and daily rate.
  3. Admin changes availability or deletes a car with no booking history.
  4. API checks role and data, then EF Core saves to SQLite.
  5. Updated fleet is returned to the browser and re-displayed.
  6. Admin can inspect database tables in the read-only viewer.
Every request follows the same pattern: browser → authenticated endpoint → validation/authorization → EF Core → SQLite → response.

21 / SQL — create database

SQL used to create the application tables

schema.sql defines Cars, Bookings, foreign keys, checks, defaults, and a booking lookup index.

CREATE FLEET TABLE
CREATE TABLE IF NOT EXISTS Cars (
  Id INTEGER PRIMARY KEY AUTOINCREMENT,
  Make TEXT NOT NULL CHECK(length(Make) <= 80),
  Model TEXT NOT NULL CHECK(length(Model) <= 80),
  Year INTEGER NOT NULL,
  DailyRate NUMERIC NOT NULL CHECK(DailyRate > 0),
  IsAvailable INTEGER NOT NULL DEFAULT 1
);
CREATE BOOKINGS + INDEX
CREATE TABLE IF NOT EXISTS Bookings (
  Id INTEGER PRIMARY KEY AUTOINCREMENT,
  CarId INTEGER NOT NULL,
  UserId TEXT NOT NULL,
  StartDate TEXT NOT NULL, EndDate TEXT NOT NULL,
  TotalPrice NUMERIC NOT NULL,
  Status TEXT NOT NULL DEFAULT 'Confirmed',
  CreatedAtUtc TEXT NOT NULL,
  FOREIGN KEY (CarId) REFERENCES Cars(Id)
    ON DELETE RESTRICT,
  FOREIGN KEY (UserId) REFERENCES AspNetUsers(Id)
    ON DELETE RESTRICT
);
CREATE INDEX IF NOT EXISTS IX_Bookings_CarId_StartDate_EndDate
  ON Bookings(CarId, StartDate, EndDate);
At startup, the app also runs EnsureCreatedAsync() for EF/Identity tables and executes CREATE TABLE IF NOT EXISTS Bookings plus CREATE INDEX IF NOT EXISTS. The SQL script is a schema reference; Identity owns AspNetUsers.

22 / SQL — access data

Main database queries and what they do

These are the key SQLite operations or their SQL equivalents. Most CRUD statements are generated by EF Core from C#.

OPERATIONREPRESENTATIVE SQLUSE
List fleetSELECT * FROM Cars ORDER BY Id;Show fleet in stable order.
Get one carSELECT * FROM Cars WHERE Id = ?;Find by primary key.
Check date overlapSELECT EXISTS (SELECT 1 FROM Bookings WHERE CarId = ? AND Status = 'Confirmed' AND StartDate <= ? AND EndDate >= ?);Reject overlapping confirmed bookings.
Insert reservationINSERT INTO Bookings (CarId, UserId, StartDate, EndDate, TotalPrice, Status, CreatedAtUtc) VALUES (?, ?, ?, ?, ?, 'Confirmed', ?);Save valid booking (EF Core SaveChanges).
My bookingsSELECT ... FROM Bookings WHERE UserId = ? ORDER BY CreatedAtUtc DESC;Only show signed-in member's records.
Cancel reservationUPDATE Bookings SET Status = 'Cancelled' WHERE Id = ?;Record cancellation without deleting history.
The overlap check is existing.StartDate ≤ requested.EndDate AND existing.EndDate ≥ requested.StartDate. “?” means a parameter supplied safely by EF Core, not string-concatenated user input.
